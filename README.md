# Obsidian 素材库

为当前项目挑选素材，先读 [AI 使用入口](AI使用入口.md) 和 [AI 选材索引](_索引/AI选材索引.md)。支持本机、GitHub 与手动复制；原卡保留事实，索引负责初筛。

这是一个长期使用的 Obsidian 素材库，同时作为 GitHub 私密仓库进行同步和备份。

## 这个库用来做什么

这个库用来沉淀一切未来可能复用的素材，包括但不限于：

- 链接、网页、X 内容
- UI 设计参考、按钮、动效、组件、页面
- 代码片段、脚本、提示词、Codex Skill、工作流
- 开源项目、工具网站、服务平台
- 文案、标题、表达句式、社媒参考
- 段子、评论、梗图、营销案例
- 产品想法、研究资料、账号人物
- 日常工作记录、周总结、月总结、阶段复盘
- 生活经验、商业观察、学习方法等后续可能新增的长期分类

这个库的核心目标不是单纯收藏，而是把素材整理成未来可直接调用的卡片。

## 日常怎么使用

## 工作快速入口

如果你主要是用这个库来记工作，优先点这几个入口：

- [00-工作入口](00-工作入口.md)
- [工作索引](_索引/工作索引.md)
- [12-工作记录/README](12-工作记录/README.md)
- [今日工作记录](12-工作记录/日记录/2026-07-02-工作记录.md)

后续日常使用时，用户只需要把内容发进来，例如：

- `收录：这个链接`
- `这个存一下`
- `这个以后可能用得上`
- `收藏这个：某个网页 / 提示词 / 代码 / 灵感`

代理会自动完成：

1. 判断内容类型和价值
2. 选择合适分类
3. 生成独立 Markdown 卡片
4. 更新索引
5. 提交并推送到 GitHub

如果你是在记录工作，也可以直接发：

- `工作记录：今天做了什么`
- `记一下今天工作`
- `帮我做周总结`
- `帮我做月总结`

代理会把内容写入 `12-工作记录/`，并同步维护工作索引。

## 卡片规则

每条新内容都先变成一张独立卡片，文件命名统一为：

`中文短标题-YYYY-MM-DD.md`

工作记录类卡片例外，可以继续把日期放在前面，方便按天、按周、按月回看。

每张卡片都包含：

- 标题
- 类型
- 分类
- 来源
- 创建时间
- 标签
- 状态
- 价值评分
- 可用于
- 相关项目
- 一句话价值
- AI 选用指南：条件、排除项、复用方式、输入输出、首读入口、同类差异、前提和检索词
- 内容摘要
- 为什么值得收藏
- 未来可以怎么用
- 原始内容或链接
- 相关联想
- 适合反向调用的场景

## 分类怎么维护

当前目录结构是初始版本，不是最终固定版本。

维护原则如下：

1. 优先使用已有分类或已有子目录。
2. 不确定内容先进入 `00-收集箱/`，标记为 `待判断`。
3. 如果某类内容明显会长期持续出现，可以新增中文分类。
4. 新增一级分类时编号顺延，并同步更新规则和索引。
5. 每次分类变更都记录在 `_索引/分类变更记录.md`。

## 同步方式

这个 Vault 会作为 GitHub 私密仓库同步和备份。

标准流程：

1. 收录前先同步最新版本
2. 收录和索引更新完成后提交
3. 推送到远程仓库

首次初始化时，如果本地还没有远程仓库，会先完成本地提交，再根据当前权限决定是否自动创建 GitHub 私密仓库。
