## 校验与保护

在仓库根目录运行：

```bash
python3 _维护/检查收藏附件.py
python3 _维护/测试附件校验.py
```

校验覆盖收藏核心属性、目录分类、日期后缀、标准章节、八项选用说明、四个核心索引、库内链接、预览附件存在性及基本格式特征。工作记录和历史副本不套用收藏章节要求。

提交时检查实际 Git 暂存内容，推送时检查实际推送版本，防止图片只存在本机但没有加入 Git。远端工作流重复执行测试和版本校验。基本文件格式检查不能代替逐页视觉验收或完整的媒体解码测试。

本机安装保护：

```bash
python3 _维护/安装本机保护.py
```

macOS 任务每分钟检查本机已跟踪内容，并从 Git 已提交版本恢复缺失的附件。它保留现有编辑，跳过已暂存的有意删除，不拉取远端、不自动提交，也不覆盖笔记。对尚未提交过的原图，Git 无法恢复，需要在首次收录时完成附件提交。

从 2026-10-13 起，macOS 不再使用 launchd 定时任务：它默认没有“文稿”目录授权，会持续失败且不能补齐外部收录器只同步 Markdown 的情况。安装命令会把「Glint 收藏预览同步」插件装进当前实际打开的 Obsidian Vault，并启用它。插件启动时及每五分钟读取 GitHub 的 `_附件/收藏预览/` 清单，只下载本机缺失的媒体；下载会先验大小和文件头、临时落盘后原子改名，绝不覆盖已有文件或笔记。状态栏会显示“预览同步：正常”或本次补回数量。

Git 钩子与远端工作流继续负责提交版本的完整性校验；Obsidian 插件负责本机镜像恢复，两者缺一不可。新机器克隆仓库后要重新运行安装命令，并在 Obsidian 的“第三方插件”中确认「Glint 收藏预览同步」已启用。
